3  tidyverse

En stor del utav statistisk analys omfattar bearbetning av datamaterial som samlats in till ett format som lämpar sig för olika statistiska analysmetoder. Ett datamaterial som man själv samlar in (primärdata) eller datamaterial som hämtas från någon annan källa (sekundärdata) är inte alltid strukturerat på det sätt som vi, eller metoderna, önskar.

För att underlätta denna process finns en samling paket kallat tidyverse som har en gemensam grund för programmering, både i dess syntax och grammatik.

Inom statistik önskas data ofta följa formatet: “en rad är en observation”, “en kolumn är en variabel” och “en cell är ett värde”, så att vi med lätthet kan hantera datamaterialet på ett flertal olika sätt. Detta kan vi kalla för rådata eller tidy data som tidyverse också använder sig av. Exempel på en struktur som inte följer denna praxis är frekvenstabeller där varje rad visar flera observationer som har samma variabelvärde. Denna typ av sekundärdata kan vi ofta stöta på vilket kan komplicera vad vi kan analysera.

Vi kan installera de paketen som ingår i tidyverse genom att installera paketet med samma namn och ladda in det i arbetsminnet med require() eller library(). Vi får nu alla paket som tidyverse innehåller installerade och laddade på ett effektivt sätt.

install.packages("tidyverse")

require(tidyverse)

I detta kapitel kommer vi gå igenom de olika paketen som behandlar datastrukturer och olika variablertyper medan senare kapitel kommer fortsätta med paket för visualisering (ggplot2) och mer avancerad kodning (purrr).

3.1 Koppla samman funktioner med pipes

Inom programmering, speciellt databearbetning, är det vanligt att vi vill skapa ett objekt, göra någon bearbetning på den, använda den i en statistisk analys och så vidare. Att nästla funktioner inuti varandra blir lätt väldigt krångligt att läsa och förstå vad som faktiskt händer eller vilka argument som hör till vilken funktion. Alternativet är att spara om objektet flera gånger men då skapas många onödiga objekt som vi måste hålla koll på och som egentligen bara tar upp plats i arbetsminnet. I kodexemplet nedan ser vi hur fyra funktioner kan nästlas eller sparas som separata objekt.

# Fyra nästlade funktioner som ska appliceras på ett objekt med olika argument
funktion4(funktion3(funktion2(funktion1(objekt), argument2 = X)), argument4 = Y)

# Fyra funktioner som sparas vid varje steg
A <- funktion1(objekt)

B <- funktion2(A, argument2 = X)

C <- funktion3(B)

D <- funktion4(C, argument4 = Y)

Inom modern R-programmering används istället en annan process som kallas för programmeringspipes som kan skapa sekvenser av funktioner som är sammanlänkade i varandra. Detta populariserades först inom tidyverse och har sedan integrerats inuti baspaketet i R.

Från baspaketet används operatorn |> som kan skapas med kortkommandot CTRL + SHIFT + M (CMD + SHIFT + M). Denna operator tar resultatet från funktionen innan |> och skickar vidare det som det första argumentet i funktionen efter |>. Koden nedan visar samma fyra funktioner som vi ville genomföra på ett objekt, där varje ny rad tar resultatet från den tidigare som en del av funktionen.

# Samma operation av fyra funktioner men med piping
objekt |> 
  funktion1() |> 
  funktion2(argument2 = X) |> 
  funktion3() |> 
  funktion4(argument4 = Y)

Funktioner som inte behöver fler än ett argument skrivs bara ut som funktionen med tomma parenteser då resultatet från raden innan används automatiskt som värdet på det argumentet. Funktioner som har ytterligare argument behöver bara ange de argument som inte använder sig av det tidigare resultatet.

Viktigt

Det kan finnas funktioner som vill använda det tidigare resultatet i ett argument som inte är den första i funktionen. Som tur är kan vi lösa detta genom att använda _ som symbolen för det tidigare resultatet och ange det vid argumentet som är aktuellt.

# Objektet (_) läggs här in som värde för det andra argumentet i funktionen
objekt |> 
  funktion5(argument1 = X, argument2 = _)

Användandet av _ säger åt funktionen att den inte längre automatiskt ska ange resultatet som värdet i det första argumentet.

|> är något begränsat med denna funktionalitet men som tur är finns dess “kusin” %>% från paketet dplyr som fungerar på mestadels samma sätt men tillåter mer flexibilitet var objektet från tidigare i pipen placeras i den nuvarande funktionen. Det vi måste tänka på är att vi här byter symbol till . istället för _ för att beskriva objektet.

# Objektet (.) läggs här in som värde för det andra argumentet i funktionen
objekt %>% 
  funktion5(argument1 = X, argument2 = .)

I resterande del av detta underlag kommer vi konsekvent att använda |> istället för dplyrs funktion. Det är i relativt abstrakta specialfall som %>% funktionaliteten behövs som inte täcks av detta material.

3.2 Läsa in filer med readr

R innehåller många inbyggda funktioner (se Avsnitt 2.2) för hur man kan läsa in filer av olika format från hårddisken. Vi har tidigare tittat på read.csv2() som är en grundfunktion i R, men readr har liknande funktioner, samt flera andra specialfall, som utgår från vissa standardformat för filer.

Tips

Det är starkt rekommenderat att läsa in text-filer i R, inte Excelfiler (.xlsx). Excel kan innehålla specialformat som R inte kan läsa in korrekt utan behov av speciallösningar.

Vi kan från Excel enkelt spara om en .xlsx fil till en .txt-, .tsv- eller .csv-fil för lättare import.

Det finns i huvudsak fyra olika vanliga typer av data som ska läsas in:

  • .txt filer där kolumner separeras med en eller flera mellanslag
  • .csv filer där kolumner separeras med , eller ;
  • .tsv filer där kolumner separeras med tab-avstånd

Var och en av dessa filer har en specifik read_X() funktion kopplat till sig med standardvärden som underlättar inläsningen.

# Läser in en textfil där kolumner separeras med en (eller flera) mellanslag (.txt)
read_table(file = "sökväg")

# Läser in en textfil där kolumner separeras med tab (.tsv)
read_tsv(file = "sökväg")

# Läser in en textfil där kolumner separeras med , (read_csv) eller ; (read_csv2)
read_csv(file = "sökväg")
read_csv2(file = "sökväg")
Noteratibble

Resultatet av dessa funktioner blir en formatterad tibble, vilket är tidyverse version av en data frame. Allting som vi tidigare introducerat för en data frame gäller fortfarande men en tibble har mer funktionalitet som vi kan dra nytta av med alla de funktioner som tidyverse erhåller.

Viktigt

Ett mycket viktigt steg i datainläsningen är att data faktiskt importerats korrekt. Dubbelkolla alltdi att datamaterialet som laddats in ser ut som vi förväntar att det ska göra, exempelvis är decimaler korrekt angivna, har vi lika många variabler i R som i originalfilen och liknande.

Detta kan vi göra genom att klicka på den importerade objektet i Environment fönstret. Vi kan också få en överblick av objektet och dess struktur genom att klicka på den blå pilen till vänster om objektnamnet. Då vecklas raden ut och visar vilka variabler som objektet innehåller och vilken typ av variabel R anser dessa är. Här är det viktigt att dubbelkolla att numeriska värden också blivit numeric i R, då det är lätt hänt att decimalseparatorn inte lästs in korrekt och R felaktigt tror det är en character istället.

3.3 Dataobjektet tibble

I Avsnitt 1.2.4.3 presenterades datastrukturen data frame som ett sätt för oss att i R spara information i ett strukturerat rådataformat. En tibble är en utbyggnad av denna datastruktur som rensat bort egenskaper av objektet som inte längre används i modern programmering och lägger till egenskaper som vi ofta vill använda när vi bearbetar data. Likt en data frame, innehåller en tibble en samling kolumner av lika längd och dessa kolumner kan vara av olika objekttyper.

Viktigt

En tibble konverterar inte textvektorer till faktorer per automatik. Det vill säga om ett datamaterial som läses in via read_csv2() innehåller text, kommer denna variabel vara ett character-objekt, inte ett Factor-objekt.

Vi kan skapa en tibble från grunden genom funktionen tibble() om vi anger vilka objekt vi vill inkludera och vad de ska heta:

a <- c(1, 2, 3)
b <- c(4, 5, 6)
c <- c("a", "b", "c")

# Skapar en tibble utifrån angivna vektorer
data <- 
  tibble(
    Var1 = a,
    Var2 = b,
    Var3 = c
  )

# Skriver ut tibble till konsollen
print(data)
# A tibble: 3 × 3
   Var1  Var2 Var3 
  <dbl> <dbl> <chr>
1     1     4 a    
2     2     5 b    
3     3     6 c

En direkt utskrift av en tibble innehåller både dimensionerna av hela objektet och vad för typ respektive variabel är. Mer information än vad vi skulle fått från en data frame över samma data.

Om vi har en matris eller något annat objekt som ser ut som en tibble men inte är det, kan vi konvertera den till en tibble med hjälp av as_tibble().

# Tar objektet a (en vektor) och gör om den till formatet tibble innehållande en kolumn
vectorToTibble <- as_tibble(a)

print(vectorToTibble)
# A tibble: 3 × 1
  value
  <dbl>
1     1
2     2
3     3

3.4 Omformatera data med tidyr

En utav de tyngsta delarna av statistisk analys är ofta att bearbeta data till det format som önskas. Paketet tidyr innehåller ett flertal funktioner som kan bearbeta data på många olika sätt, med målsättingen att göra den “tidy”. Detta paket kommer vi inte titta på just nu i detalj men följande Cheat Sheets innehåller exempel på olika bearbetningar som vi kan vara intresserade av att genomföra med data.

Tips

Många paket har liknande Cheat Sheets med en sammanfattning av paketets funktioner. Dessa sheets kommer väl till pass både när man först lär sig om paketet och när man sedan ska använda det, för det är inte alltid man kommer ihåg exakta funktionerna som behövs för att göra en viss operation.

Testa alltid att söka efter “paket cheat sheet” i din föredragna sökmotor för att se om det paket som du ska arbeta med också har något sådant.

3.5 Databearbetning med dplyr

Nu har vi lärt oss hur vi läser in data från en text fil, vad en tibble är och det “nya” sättet att skriva sekvenser av funktioner med pipes. Då kan vi börja titta närmare på databearbetning av objekt. I detta kapitel förutsätter vi att vi har data på tidy format.

Det är vanligt att vi i databearbetningen behöver göra flera steg för att skapa det objekt vi sen vill analysera och då kommer |> mycket väl till pass.

Paketet dplyr innehåller ett flertal olika “verb” som på ett sätt eller annat bearbetar data. Det första argumentet i alla dessa funktioner är ett dataobjekt men om vi använder pipes kommer det ske per automatik och vi behöver endast fokusera på de andra argumenten som beskriver hur “verbet” används.

3.5.1 Byta namn på variabler med rename()

Data som läses in till R kan ibland ha konstiga och långa namn som vid programmering kan bli svåra att hantera. Ett sätt att underlätta detta problem är att döpa om variablerna till ett enkelt ord som vi sedan kan använda i efterföljande steg.

Vi kan döpa om variabler med hjälp av rename() där vi anger det nya namnet givet det gamla namnet på variabeln eller variabelns kolumnindex. 3.5.2 Plocka ut rader med filter()

Om vi är intresserade av att plocka ut vissa rader ur ett objekt, till exempel om vi vill rensa bort saknade värden, kan vi använda filter() med någon logisk operator som säger vilka rader vi vill ha kvar.

ViktigtLogiska operatorer

En logisk operator är ett uttryck vars resultat är sant eller falskt (TRUE eller FALSE). Det finns många olika operationer som vi kan använda för olika ändamål:

  • a == b: a är lika med b. *Notera användningen av dubbla == för den logiska operationen till skillnad från = för att säga att a har värdet b.
  • a > b: a är större än b,
  • a >= b: a är större än eller lika med b,
  • a < b: a är mindre än b,
  • a <= b: a är mindre än eller lika med b,
  • a != b: a är inte lika med b.
# Väljer ut alla observationer vars väntetid är större än 70 minuter
faithfulLong <- 
  faithful |> 
    filter(waiting > 70)

print(faithfulLong)
# A tibble: 165 × 2
   eruptions waiting
       <dbl>   <dbl>
 1      3.6       79
 2      3.33      74
 3      4.53      85
 4      4.7       88
 5      3.6       85
 6      4.35      85
 7      3.92      84
 8      4.2       78
 9      4.7       83
10      4.8       84
# ℹ 155 more rows
Notera

Notera att eftersom vi inte sparade de omnämnda variabelnamnen i föregående kapitel så kan vi inte använda dessa i fortsatta bearbetningar. Objektet faithful består här fortfarande av de engelska namnen.

Vi kan också använda negativa operationer för att plocka ut observationer som inte uppfyller ett visst kriterie. Vi använder då operatorn ! runt hela uttrycket som betyder “icke”.

faithful |> 
  filter(!(waiting > 70))

3.5.4 Byta plats på variabler med relocate()

Ibland kan vi vilja byta ordning på variablerna i datamaterialet utan att specifikt plocka ut enbart dem. 3.5.6 Skapa nya variabler med mutate()

3.5.7 Gruppera beräkningar med group_by()

Många gånger vill vi genomföra beräkningar separat för olika grupper i datamaterialet. För att göra detta använder vi group_by(), som delar upp observationerna i grupper baserat på värdena i en eller flera variabler.

Notera

Eftersom datamaterialet faithful endast innehåller numeriska variabler skapar vi först en gruppvariabel som delar in observationerna i korta och långa väntetider. Vi använder if_else() för att ge den nya variabeln ett värde om uttrycket uppfylls (Short wait), ett annat om det inte uppfylls (Long wait).

faithful <- 
  faithful |>
  mutate(
    waitLength = if_else(waiting < 70, "Short wait", "Long wait")
  )

3.5.8 Sammanfatta data med summarize()

Funktionen summarize() används för att beräkna sammanfattande mått, till exempel medelvärden, summor eller antal observationer. Resultatet blir ett nytt objekt där varje rad motsvarar en sammanfattning av hela datamaterialet eller av varje grupp.

# Beräknar medelvärdet av väntetiden
faithful |>
  summarize(
    meanWait = mean(waiting)
  )
# A tibble: 1 × 1
  meanWait
     <dbl>
1     70.9

Vi kan beräkna flera sammanfattande mått samtidigt.

faithful |>
  summarize(
    meanWait = mean(waiting),
    minWait = min(waiting),
    maxWait = max(waiting)
  )
# A tibble: 1 × 3
  meanWait minWait maxWait
     <dbl>   <dbl>   <dbl>
1     70.9      43      96

Den verkliga styrkan hos summarize() framträder när den kombineras med group_by(). Då beräknas sammanfattningarna separat för varje grupp.

faithful |>
  group_by(waitLength) |>
  summarize(
    meanWait = mean(waiting),
    n = n()
  ) |> 
  ungroup()
# A tibble: 2 × 3
  waitLength meanWait     n
  <chr>         <dbl> <int>
1 Long wait      80.5   169
2 Short wait     55.2   103
Viktigt

Det är mycket vanligt att kombinera flera funktioner från dplyr i samma kedja. Ett vanligt arbetsflöde är att först välja ut observationer med filter(), skapa nya variabler med mutate(), gruppera data med group_by() och slutligen beräkna sammanfattande mått med summarize().

faithful |>
  filter(waiting > 60) |>
  mutate(
    waitingSec = waiting * 60,
    eruptionLength = if_else(eruptions < 3, "Short", "Long")
  ) |>
  group_by(eruptionLength) |> 
  summarize(
    meanWait = mean(waitingSec)
  ) |> 
  ungroup()
# A tibble: 2 × 2
  eruptionLength meanWait
  <chr>             <dbl>
1 Long              4799.
2 Short             3849.
